# OpenRouter transcription

For live transcription with your own streaming provider key, see [Live cloud](live-transcription.md).

The personal app starts with local speech recognition and AI enhancement off. In **AI Settings > Voice Engine**, the **Local**, **OpenRouter** and **Live cloud** tabs only show settings; browsing a tab does not activate its provider. The active voice engine is shown above the tabs. To enable OpenRouter, open its tab, save a key, choose the speech model, validate it, and turn on **Use OpenRouter**. Turning OpenRouter on clears an active Live cloud provider. Turn the switch off to return to the selected local model, or activate a model in the Local tab or a provider in the Live cloud tab. Removing the key also turns OpenRouter off. The key is stored in the personal app's macOS Keychain service.

Key validation checks authentication and the supported speech and style models. Style models must support audio input, text output, and structured output. Validation cannot guarantee that your account permits a provider serving every listed model. For example, an account allowing only OpenAI, Anthropic, and Google cannot currently use the Whisper models served by Groq or DeepInfra. Review your own [OpenRouter provider permissions](https://openrouter.ai/settings/privacy) when the app reports that no provider is available. The app never changes these account restrictions, pins an underlying host, or silently switches providers.

## Model list

The speech model list follows OpenRouter's public transcription catalog. Once a key is saved, opening the OpenRouter tab or the cloud meeting settings fetches the catalog at most once every six hours, and **Validate connection** always fetches it. The request carries no credentials and no audio. The last fetched list is stored in the personal app's preferences, so it is available offline; a failed fetch keeps that list and is recorded in the debug log. A model OpenRouter withdraws disappears at the next fetch. A speech model selection pointing at it returns to the default model. A meeting selection stays visible as **no longer listed**, and meeting transcription reports that another model must be chosen. The three Whisper models (Large v3 Turbo, Large v3 and Whisper 1) and the two GPT-4o transcription models are built in and are always offered, even before the first fetch.

Being listed does not prove what a model can return. Word timestamps in particular vary by model and by the provider serving it, and the catalog does not describe them. The built-in Whisper models are documented to return word timestamps; OpenRouter serves Whisper 1 only through OpenAI, whose API documents word timestamps for it. Every other listed model is treated as plain text only until it passes the word-timing check described under [Completed meetings](#completed-meetings).

## Dictation

Dictation uploads audio after recording stops; it does not send cloud preview requests. Dictation detects any supported language automatically by default. Optional **Primary language** and **Secondary language** preferences are recognition hints where supported; they never restrict detection to those languages. During recording, the overlay offers Primary, Secondary, and **Detect automatically**. An explicit choice is remembered for later recordings; removing a selected language falls back to automatic detection. A dictation with a Cleanup Style supplies an explicitly selected language as an instruction to the style model; every other request sends it through OpenRouter's `language` field. Imported files also detect automatically and use both language preferences as optional recognition hints where supported. Each operation keeps its provider, model, hints, instructions, and credentials together; the overlay can update only the language choice of the recording in progress.

A dictation with a Cleanup Style sends language hints with the audio instructions. For the transcription endpoint, OpenRouter ignores top-level multipart `prompt` fields, so requests with hints use its documented JSON `provider.options` mechanism. Prompts are provided for OpenAI, Groq, and Together on the built-in models, without pinning a host or changing account permissions. DeepInfra prompt forwarding has not been verified and receives no prompt. Models that come only from the catalog have no verified prompt forwarding either, so they receive the explicit `language` field but no hint prompt. The serving provider may ignore hints; language coverage and mixed-language accuracy still depend on the model. See the [OpenRouter speech-to-text contract](https://openrouter.ai/docs/guides/overview/multimodal/stt).

### Two models, chosen by the Cleanup Style

Voice Engine has two model pickers, named by what they do. The **Speech model** turns speech into text; it serves dictation without a Cleanup Style, imported files, the local API and the command and rewrite modes, on OpenRouter's transcription endpoint. The **Style model** is used only when a Cleanup Style is on: after recording stops, the audio and the resolved style go to that model together on OpenRouter's chat endpoint, and it returns both the transcript and the styled text. There is no separate cleanup request and no dictation mode to choose. A line under the pickers says which model the next dictation uses. When the style resolves to **Off**, including through an app or shortcut rule, the recording goes to the speech model and the style model is not contacted.

The Style model list shows the newest audio-capable chat models OpenRouter offers, one per model family: models that accept audio input, return text and support structured outputs, refreshed together with the transcription catalog. Older generations, previews that have a stable successor, tool variants, batch variants, routers (OpenRouter's own and third-party ones, recognised by their variable price) and tilde aliases are hidden. Gemini Flash, Flash Lite and Pro come first. The default is the newest Gemini Flash listed; Gemini 3.8 Flash and Gemini 3.5 Flash Lite are built in for use before the first fetch or offline. A stored choice that is no longer offered, such as the deprecated Gemini 2.5 models, falls back to the default.

For a styled dictation the app inserts the styled text and stores both fields separately in history. The same model generates both fields, so the transcript is not an independent speech recognizer's reference or a guarantee of literal wording. App-specific rules, routing scope, and shortcut styles still determine the instructions sent. A previously selected Fluid Intelligence style uses the default cleanup instructions; its saved local preference is retained. No separate verified text AI provider is required to select, edit, or test a style. The Prompt Test editor sends its unsaved instructions with audio using the same one-request path and displays both returned fields without inserting text. Separate **AI Providers** remain available for text editing and other text AI actions.

A dictation with a Cleanup Style is limited to **8 minutes per recording**, because the whole recording travels in one request and OpenRouter caps audio input at 25 MB. A dictation without a style has no such limit: the speech model receives it in chunks of at most 120 seconds, like an imported file. A longer styled recording, unsupported model, malformed response, or provider failure reports an error; the app does not split the recording or automatically launch an extra cleanup, transcription, or local fallback request. Explicit retry starts another request. Import longer audio as a file instead, or turn the style off.

On a dictation failure, Voice Engine offers explicit **Retry and copy**, **Transcribe locally and copy**, and **Discard recording** actions. Retry uses the captured dictation settings with the current saved key. The failed recording stays in memory until retried, discarded, replaced by another failed recording, or the app exits. Local retry may need the selected local model to be downloaded. It never activates automatically. Cancellation stops requests and prevents delayed text insertion. The debug log records one line per failure naming the error kind (for example `server(400)` or `modelUnavailable`) and the model, never the transcript, audio, key or provider response.

## Imported files

Imported audio and video use the **Speech model**. Dictation without a Cleanup Style, the local HTTP API's transcription endpoint and the command and rewrite modes use the same model. The default is `openai/whisper-large-v3-turbo`; GPT-4o Transcribe, GPT-4o Mini Transcribe, and every other model in the transcription catalog are available for plain-text output. File transcription remains a speech recognition operation and does not send Cleanup Styles. Audio is converted to mono 16 kHz WAV and uploaded in chunks of at most 120 seconds. Requests requiring word timestamps use a one-second overlap and timestamp ownership to avoid duplicate words. Plain-text requests use non-overlapping chunks. Full decoded audio is currently held in memory, so very long imports can use substantial RAM even though each upload is bounded.

Completed file chunks are saved locally using an audio fingerprint and the complete transcription configuration. Retrying the same file and settings reuses completed chunks. Changing the model or language hints starts a distinct transcription. The cache contains transcript text and follows the personal app's local data backups. Short dictation does not persist this chunk cache.

## Completed meetings

Meeting settings have a separate OpenRouter model selection, defaulting to `openai/whisper-large-v3`. The meeting pipeline aligns each word to a locally detected speaker turn, so the list only offers models with verified word timestamps: the three built-in Whisper models, plus any catalog model that passed the word-timing check on this Mac.

**Check catalog models for word timings** runs that check over every catalog model that has not been checked yet. The app synthesizes a four-second spoken phrase with the macOS system voice and sends that clip, never your audio, to each model with a request for word timestamps. Each model costs one ordinary billed request, two when the model rejects the timestamp request and the clip is retried as plain text; all of them appear in the recorded usage. A model that returns usable timestamps joins the list. A model that transcribes the clip without usable timestamps, or rejects the timestamp request while still transcribing plain text, is remembered as lacking them and stays hidden. Any other failure, such as a provider your account does not allow or an empty transcript, proves nothing and leaves the model unchecked; a rejected key, missing credits or rate limiting stops the run. Once every model has a verdict the button rechecks the refusals, so a provider that adds timestamps later can be picked up without an app update. Results are stored in the personal app's preferences. A passing check on a short clip shows the model can return timestamps; it does not guarantee them for every meeting chunk, so the runtime validation below still applies.

OpenRouter's own catalog notes name word-level timestamps for Whisper Large V3, Whisper 1, MAI-Transcribe 2, Qwen3 ASR 0.6B and 1.7B, Grok STT 1.0, Gemini 3.5 Transcribe, Fish Audio Transcribe 1 and 1 Pro, and AssemblyAI Universal-3.5 Pro, and its transcription guide names OpenAI, Groq, Deepgram, Mistral and Azure as endpoints that can return timestamps. Those notes are hints only; the check is what admits a model. AssemblyAI through OpenRouter accepts WAV only and at most 120 seconds per request, which meeting chunks and file chunks respect.

Local Nemotron still identifies speakers. Track separation, echo handling, speaker matching, and transcript assembly use the existing shared meeting pipeline.

Automatic and supported manual language selection apply to the completed cloud transcript. With OpenRouter, live captions run on this Mac in English; the **Live cloud** choice streams captions and the transcript from a live provider instead (see [Live cloud transcription](live-transcription.md#meetings-fluidmeet)). Missing or invalid word timestamps produce an incomplete result with an actionable error; the app never invents timestamps. Retrying a meeting can reuse successful recognition chunks with the same audio and frozen configuration.

Optional speaker labels for imported audio use local diarization aligned against one timed cloud transcript, so they also need a model with verified word timestamps. The check runs from meeting settings with OpenRouter selected there and does not change the meeting model. Words with no confident speaker remain unassigned. Speaker labels for imported video are not supported in this release; disable that option to transcribe video as plain text.

## Meeting summaries

The personal build has no on-device summary model, so a completed meeting is summarized by the text AI provider selected in **AI Settings > AI Providers**, with the model chosen there. When that provider is OpenRouter without its own key, or when no usable text provider is selected, the summary uses OpenRouter with the Voice Engine key and the selected Dictation model, because that key also authorizes OpenRouter's chat endpoint. With neither available, the summary panel asks for an AI provider.

Summaries run only when **Summarize** is pressed. The request sends the meeting title, date, duration, participant names and the speaker-labelled transcript, never audio, and streams the answer into the panel. Each summary type (executive, detailed, action items, decisions, participants, topics) has its own instructions; all of them tell the model to use only the transcript and to answer in the language the meeting was held in. A request is limited to about 400 KB of transcript text and ten minutes. A summary is saved next to the meeting and reappears for the same transcript, even after switching to another cloud model; editing the transcript or a speaker name hides it until it is regenerated. Cloud summaries do not pause dictation or unload local models.

## Text fidelity, costs, and privacy

Cloud recognition preserves the returned transcript. Dictation history stores optional styled text separately; styling remains off until explicitly configured. For dictation both fields come from the same generative model response. Recognition itself can still normalize numbers or punctuation. A literal transcript is not guaranteed by any model.

Voice Engine shows recorded request costs and processing times, including dictation. Dictation requests charge for audio input and text output. Missing costs appear as **unknown**, and totals identify requests with unavailable costs. These are provider-reported amounts, not a billing guarantee. Cached chunks do not create new usage entries. Request diagnostics include metadata only, never API keys, audio bodies, or transcript content. Each request logs its upload size and duration, never its content.

Imported files, the local API, and command and rewrite recordings upload lossless FLAC, a fraction of the size of WAV. Dictation keeps WAV, because the chat endpoint it uses accepts WAV and MP3 only. The app keeps one connection to OpenRouter open during a recording so the request can start as soon as you stop.

Audio leaves the Mac only when a cloud operation is selected. Meeting summaries send transcript text, not audio, to the summary provider described above. The word-timing check sends only a synthesized phrase. The catalog fetch sends no audio, credentials, or settings, and does not run until a key is saved. Dictation also sends your selected instructions. App/window context and preceding text are sent only when the selected custom style enables context; they are omitted by default and in prompt tests. OpenRouter routes requests according to account eligibility and available providers. Its transcription endpoint does not currently honor per-request provider-pinning controls. Transcripts, styled text, resumable chunks, usage metadata, and recordings stay under the personal app's isolated local storage. See [maintenance and rollback](maintenance.md) for backup locations.

The public source build excludes the private Fluid Intelligence runtime. Existing optional external enhancement remains available. Direct OpenAI/Groq clients, custom speech endpoints, iPhone support, and public binary distribution are outside this release.
